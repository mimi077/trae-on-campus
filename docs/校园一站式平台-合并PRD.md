## 1. 项目目标

**一句话目标**：让学生用一个学号登录，就能同时完成「闲置物品怎么流转」和「校园活动怎么参加」两件高频事务；让老师在同一后台完成活动发布、活动与失物审核、名单与记录管理。

**产品契约**：

| 项 | 定义 |
| --- | --- |
| 主要用户 | 在校学生（买卖闲置、找失物、报名活动）；教师 / 活动事务处（发布与审核） |
| 触发场景 | 想处理闲置物品、丢了/捡到东西、想参加或组织活动 |
| 核心任务 | 三个独立闭环 + 一个共享身份与通知入口 |
| 完成条件 | 闲置可发布/收藏/成交；失物可发布/审核/留言；活动可发布/审核/报名/看名单 |
| 信任基础 | 学号 / 工号实名、官方认证、服务端审核与审计日志 |

**MVP 判定标准**：三个域各有一条可连续演示的完整闭环，且共享同一登录态、导航、个人中心与通知入口；V5 原有主流程不出现回归。

**成功标志（可验收）**：

1. 学生用学号登录后，侧栏同时看到「闲置广场 / 失物招领 / 活动广场」，三个入口均可用。
2. 闲置域完整保持 V5 行为：发布带流转标签的商品、14 天到期提醒、收藏、聊天均正常。
3. 教师发布官方活动 → 学生筛选发现 → 报名成功、名额实时变化 → 教师查看名单。
4. 社团提交活动与失物信息均进入各自审核队列，驳回需填原因，公开列表只显示已通过内容。
5. 顶栏通知铃铛同时汇总「闲置到期」「活动即将开始」「待审核（教师）」，三类提醒互不干扰。

## 5. 业务规则、边界约束与并发风险（核心章节）

> 原则：前端校验只做体验优化，**关键规则必须在后端再校验一次**；三域规则各自独立，合并只共享基础设施，不共享业务状态。

### 5.1 统一身份与时序

| 规则 | 说明 | 校验位置 |
| --- | --- | --- |
| 登录前置 | 学号 / 工号存在且未禁用；首次登录同步身份资料 | 后端 |
| 会话 | httpOnly Cookie + Session 表，过期需重新登录 | 后端 |
| 角色判定 | 以数据库 `role` 为准，请求携带会话解析 | tRPC Context |
| 页面守卫 | 未登录访问三域页面统一跳转 `/login` | middleware |
| 跨域身份一致 | 三个域共用同一 `userId`，不存在“闲置账号”和“活动账号” | 数据模型 |

### 5.2 闲置域规则（※ 不可变更）

| 规则 | 说明 |
| --- | --- |
| 到期下架 ※ | 发布后 14 天自动 `EXPIRED`，公开列表隐藏，仅本人在「我的发布」可见 |
| 重新上架 | 本人操作，续期 14 天；删除为硬删除并清理收藏、意向、出价与聊天来源 |
| 流转标签 ※ | 急出 / 可小刀 / 只自提 / 可换物，发布与编辑时可多选，卡片按标签着色 |
| 状态边界 ※ | 非 `ON_SALE` 商品禁止收藏、意向收藏、出价、发起聊天 |
| 赠予边界 ※ | 赠予价格必须为 0 元；赠予需发布者审批 |
| 收藏幂等 ※ | 同一用户重复收藏同一商品返回已有记录，不产生重复数据 |
| 聊天锁 ※ | 已有出价会话后，普通消息发送受会话状态约束 |
| 公开列表 ※ | 只返回 `ON_SALE`；`EXPIRED` 不进入任何公开查询 |

> 以上行为在合并版本中**逐条保持不变**，只允许把“到期提醒”展示位置并入统一通知中心，判断逻辑与接口签名不改。

### 5.3 活动域名额互斥（并发核心）

| 资源 | 互斥条件 | 冲突后果 | 处理方式 |
| --- | --- | --- | --- |
| 活动名额 | `已占用 < capacity` 才可创建报名 | 超卖 | 事务内查 → 判断 → 写入，已满返回 `CAPACITY_FULL` |
| 同一用户同一活动 | `userId + activityId` 唯一 | 重复报名占多个名额 | 唯一索引 + 幂等返回 |
| 审核动作 | 仅 `PENDING` 可审核一次 | 重复审核、状态跳变 | 带状态条件更新 |
| 取消与回补 | 取消成功即释放名额 | 名额泄漏 | 取消与计数同一事务 |
| 活动取消 | 仅 `PUBLISHED` / `ONGOING` 可取消 | 已结束被误取消 | 状态机 + 二次确认 |

**名额口径（全文唯一）**：`已占用 = PENDING + APPROVED 的报名数`；`剩余 = max(capacity - 已占用, 0)`。

### 5.4 失物域审核规则（保持不变）

| 规则 | 说明 |
| --- | --- |
| 发布即待审 | 新信息 `PENDING`，公开列表只返回 `APPROVED` |
| 可见性 | 未通过仅发布者与管理员可见，普通用户访问详情返回不存在 |
| 驳回必填原因 | 原因展示在「我的失物发布」 |
| 留言边界 | 仅已通过可留言；已结束关闭留言；不能给自己留言 |
| 时间边界 | 丢失 / 捡到时间不得晚于当前时间 |

### 5.5 跨域边界（合并新增，评审重点）

| 场景 | 规则 | 原因 |
| --- | --- | --- |
| 删除闲置 | 只清理该商品的收藏、意向、出价与聊天，不影响活动报名、失物记录 | 业务域隔离 |
| 活动取消 | 只联动报名状态，不改用户闲置数据 | 业务域隔离 |
| 失物标记结束 | 不影响同用户发布的其他失物与闲置 | 记录级隔离 |
| 审核权限 | 活动审核只能改活动，失物审核只能改失物 | 防止越权串操作 |
| 教师查看范围 | 教师可看活动报名名单，但**不能**查看学生聊天、收藏、出价 | 隐私最小化 |
| 通知点击 | 通知只做跳转，不修改任何域状态 | 避免隐式写操作 |
| 统一搜索（P1） | 不跨域返回未审核内容；活动与失物仅返回公开状态 | 防止审核绕过 |
| 账号禁用 | 禁用后三域同时不可读写，会话立即失效 | 统一身份 |
| 数据统计 | 概览统计按域分别计算，不把闲置数算进活动参与 | 指标口径 |

### 5.6 次数与身份边界

| 规则 | 说明 |
| --- | --- |
| 同一活动单用户 | 一条有效报名；取消后可重新报名，生成新记录 |
| 并发报名上限 | 同一学生最多同时持有 20 个未结束活动报名 `[假设]` |
| 发布者限制 | 教师不能报名自己发布的活动 |
| 闲置发布上限 | 单用户同时在售 50 件 `[假设]` |
| 重复提交 | 10 秒内相同用户 + 相同对象 + 相同操作返回已有结果 |
| 前端限制 | 提交中按钮置灰、Loading，仅体验优化 |

### 5.7 输入与数据边界

| 域 | 关键边界 |
| --- | --- |
| 闲置 | 标题 2–60、描述 2000、价格 0–99999、图片链接 http(s)、分类与成色枚举 |
| 失物 | 标题 2–60、地点 2–60、描述 500、联系方式 60、时间不晚于当前 |
| 活动 | 标题 2–60、地点 2–60、简介 500、详情 5000、名额 1–2000、链接 500、`startAt < endAt`、`deadline <= startAt` |
| 通用 | 链接仅 http(s)，拒绝 `javascript:` / `data:`；枚举非法值直接拒绝 |
| 规模 | 商品 500、失物 500、活动 500、报名 5000；列表 12 条/页 |
| 数据策略 | SQLite 持久化；线上演示环境 `/tmp` 重启重置，属可接受限制 |

### 5.8 三套状态机并存

| 对象 | 状态 | 自动流转 |
| --- | --- | --- |
| 商品 | `ON_SALE` / `SOLD_OUT` / `EXPIRED` | 14 天到期惰性置 `EXPIRED`（V5 不变） |
| 失物 | `PENDING` / `APPROVED` / `REJECTED` / `CLOSED` | 无自动流转，人工结束 |
| 活动 | `DRAFT` / `PENDING` / `PUBLISHED` / `ONGOING` / `ENDED` / `CANCELLED` / `REJECTED` | 到达开始/结束时间惰性流转 |
| 报名 | `PENDING` / `APPROVED` / `REJECTED` / `CANCELLED`（`ATTENDED` P1） | 活动取消时联动 `CANCELLED` |

> 三套状态机**互不读写**；共享的只有“惰性计算”这一实现模式。

### 5.9 外链与内容安全

1. 活动外链、闲置图片链接、失物图片链接统一按 `http(s)` 校验。
2. 外链报名先二次确认，`new tab` + `rel="noopener noreferrer"`，平台不代理内容。
3. 活动标题与详情禁止无关广告引流；审核驳回需写明原因。
4. 公开名单只显示「学院 + 姓名首字」，完整名单仅教师可见。
5. 留言禁止填写身份证号、完整银行卡号；联系方式建议微信 / QQ 昵称。

### 5.10 教务平台对接边界

| 项 | 约定 |
| --- | --- |
| 登录 | 学号 / 工号 + 密码 → 教务身份接口；校方支持 SSO 时优先 SSO |
| 首登同步 | 姓名、学院、专业、年级；三域共用同一份资料 |
| 失败降级 | 超时 3 秒降级本地演示账号，登录页标注「演示模式」 |
| 异常身份 | 不存在、毕业、休学、冻结 → 拒绝并提示 |
| 并发首登 | upsert 保证一条用户记录 |
| 凭据安全 | 不存教务密码，只存校方标识与必要资料 |
| 回写（P1） | 活动学分 / 志愿时长批量回传，记录成功与失败可重试 |

### 5.11 UI 层级与遮挡约束

1. 所有下拉、弹窗、二级面板使用 `createPortal` 挂到 `body`，层级高于内容区（沿用 V5）。

## 8. 后端设计要点

### 8.1 数据模型全景

| 域 | 模型 | 状态 |
| --- | --- | --- |
| 身份 | `User`、`Session` | V5，扩展 `role = STUDENT / TEACHER / ADMIN`、`studentNo` |
| 闲置 | `Item`、`Favorite`、`IntentFavorite`、`WishPurchase`、`Bid`、`GiftApproval`、`Message` | V5 不变 |
| 治理 | `Report`、`AdminLog` | V5，`action` 扩展活动动作 |
| 失物 | `LostFound`、`LostFoundMessage` | V5 不变 |
| 活动 | `Activity`、`Registration`、`ActivityMessage` | 新增 |
| 可选（P1） | `FavoriteActivity`、`Notification` | 预留，不开放 |

**活动字段**：`title、type、source、organizer、startAt、endAt、registrationDeadline、location、capacity、registrationMode、externalUrl、description、coverUrl、tags、status、createdBy、reviewNote、reviewedBy`。

**枚举**：类型 `LECTURE / COMPETITION / VOLUNTEER / CLUB / CAREER / SPORTS / OTHER`；来源 `OFFICIAL / SCHOOL / COLLEGE / CLUB`；标签 `CREDIT / HOURS / PRIZE / AUDIT / MEAL`；报名方式 `INTERNAL / EXTERNAL / BOTH`。

### 8.2 共享服务与隔离

1. **会话服务**：三域统一读 `Session`，不各写一套 Cookie。
2. **审核服务**：统一 `review()` 约束（仅 PENDING、驳回必填原因、写审计），活动与失物各自表，不共用表。
3. **通知聚合**：只读查询，聚合闲置到期数、活动即将开始数、待审核数，不写业务状态。
4. **惰性流转**：`expireStaleItems()`（闲置）与 `syncActivityStatus()`（活动）独立实现，互不调用。

### 8.3 接口清单（按域）

| 域 | 接口 | 类型 | 关键校验 |
| --- | --- | --- | --- |
| 身份 | `auth.login / logout / me` | mutation/query | 角色、会话 |
| 闲置 | `item.list / byId / create / update / relist / remove / expiredCount` | 混合 | 沿用 V5，签名不变 |
| 闲置 | `favorite.* / intentFavorite.* / bid.* / gift.* / message.*` | 混合 | 沿用 V5 |
| 失物 | `lostFound.list / byId / create / myList / close / messages / addMessage / adminList / adminReview / pendingCount` | 混合 | 沿用 V5 |
| 活动 | `activity.list / byId / create / update / cancel / review / pendingCount` | 混合 | 名额、状态、权限 |
| 报名 | `registration.create / cancel / mine / roster` | 混合 | 名额互斥、时间窗口 |
| 活动留言 | `activityMessage.list / create` | 混合 | 可见性、长度 |
| 共享 | `stats.home`、`notification.summary` | query | 聚合只读 |

### 8.4 实现约束

1. 类型先行：Zod 定义输入输出，前端获得补全。
2. 校验在后端：名额、状态、权限、时间窗口全部在 mutation。
3. 写入前复核：报名与审核在事务内重读状态。
4. 统一错误结构：`TRPCError` + 明确 message。
5. 审计留痕：发布、审核、取消、删除均写 `AdminLog`。
6. **不改 V5 接口签名**；新增字段只做可选扩展。

### 8.5 并发自检清单

- [ ] 报名提交前复核已占用名额
- [ ] 重复报名不产生两条记录
- [ ] 截止与开始时间以服务端为准
- [ ] 审核只能处理 PENDING，重复审核幂等
- [ ] 取消报名后名额正确回补
- [ ] 未审核活动 / 失物不可被普通用户访问
- [ ] 闲置 14 天到期逻辑未被改坏
- [ ] 三域删除 / 取消操作互不串数据
- [ ] 权限校验在服务端，前端隐藏不作为防线
- [ ] 空数据与错误均有兜底
