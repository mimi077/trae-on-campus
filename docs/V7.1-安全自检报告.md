## 四、安全设计要点

- 所有写操作必须携带有效 Cookie 会话；匿名写操作统一 401。
- 通知可见性在 Prisma 查询层拼接条件（每个已填维度都必须等于用户对应字段），前端无法通过改参数越权。
- 通知详情越权返回 404，不泄露「存在但不可见」。
- 教师只能发布全员通知与查看自己发布的通知；定向与下架仅管理员可操作。
- 热门池仅管理员可管理；外部链接强制 `http(s)`；条目上限 8 条、重复添加被拒。
- 学生身份认证仅影响推荐与通知，不改变角色；角色仍从数据库读取。
- 单用户写操作 60 秒 60 次限流保持不变。

## 五、遗留风险

| 风险 | 建议 |
| --- | --- |
| SQLite 位于 `/tmp`，实例重启数据重置 | 正式上线换 Postgres |
| 多实例不共享 SQLite | 使用外部数据库后再横向扩容 |
| 通知编辑目前仅提供接口能力，后台 UI 以发布 / 下架为主 | 如需修订可在下一版补编辑弹窗 |
| 推荐为规则匹配，未做兴趣行为学习 | 后续可加入报名历史权重 |
| 演示账号固定密码 | 接入学校统一身份认证并移除演示账号 |
