## 二、身份与权限

三档服务端鉴权，全部在 tRPC 中间件强制校验，不信任前端传入角色：

| 过程 | 允许角色 | 典型接口 |
| --- | --- | --- |
| `publicProcedure` | 任意已登录用户（读接口允许访客） | 列表、详情、留言列表 |
| `staffProcedure` | TEACHER / ADMIN | 活动审核、失物审核、报名名单、待审数量 |
| `adminProcedure` | ADMIN | 举报处理、审计日志、管理端失物列表 |

认证来源仅两条，且均不可伪造：

1. httpOnly Cookie `campus_session` → `Session` 表校验有效期；
2. 冒烟测试头 `x-user-id` 仅在显式设置 `ALLOW_TEST_HEADER=1` 时启用，生产环境默认关闭。

未登录请求统一映射为访客身份（`id = guest`），不再回退到任何真实账号。

## 五、千人访问与容量保障

| 措施 | 说明 |
| --- | --- |
| SQLite WAL | 读写并发不互相阻塞 |
| `busy_timeout=5000` | 写锁竞争自动等待而非直接报错 |
| `synchronous=NORMAL` | 兼顾吞吐与安全 |
| 索引 | 活动 `status+startAt`、`source`、`createdBy`；报名 `activityId+status`、`userId` 与唯一索引 |
| 批量统计 | 名额占用使用一次 `groupBy`，避免 N+1 |
| 分页上限 | 列表固定分页，单页最多 10–20 条 |
| 写限流 | 单用户 60 秒最多 60 次写操作 |
| 状态惰性流转 | 30 秒节流，避免每次请求都全表更新 |
| 平台配置 | 1 vCPU / 2 GiB，最多 10 实例，100 QPS，日出口 10 GiB |

按 1000 名注册用户、峰值 100 QPS 估算，读多写少的校园场景可由单实例 + 上述索引与分页承载；平台最多 10 实例可横向扩容。

## 六、遗留风险与上线建议

| 风险 | 影响 | 建议 |
| --- | --- | --- |
| SQLite 位于 `/tmp` | 实例重启或重新部署后数据重置 | 正式上线换 Postgres / Turso |
| 多实例间不共享 `/tmp` | 不同实例可能看到不同数据 | 使用外部持久数据库后再扩容 |
| 演示账号与固定密码 | 仅适合演示 | 接入学校统一身份认证并移除演示账号 |
| 限流为单实例内存计数 | 多实例下阈值被放大 | 改用 Redis 等集中式限流 |
| 外链报名不落库 | 无法统计外部报名人数 | 后续接入外部回调或手动登记 |
